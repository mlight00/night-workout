# 야간 25분 운동 코치 앱 — 설계 문서

- 작성일: 2026-07-21
- 프로젝트 위치: `C:\workspace\personal\night-workout`
- 사용자: 1인 (개인용). 다중 사용자 지원 없음.

---

## 1. 목적

치닝디핑 머신을 이용한 야간(22시 이후) 25분 근력 루틴을, 폰 하나로 자동 진행시키는 웹앱.

세 가지를 해결한다.

1. **시간 관리** — 세트·휴식 시간을 사람이 재지 않아도 25분 안에 끝나게 자동 진행한다.
2. **버틴 시간의 실측** — 매달리기·버티기 종목은 스스로 몇 초를 버텼는지 알 수 없다. 카메라가 실제 시간을 측정한다.
3. **지속** — 밤에 지친 상태에서 앱이 한 번이라도 삐끗하면 습관이 끊긴다. 무슨 일이 있어도 운동이 멈추지 않아야 한다.

### 대상 사용자 조건

- 완전 초보, 중년
- 야간 실내 조명 (어두움)
- 안드로이드 (갤럭시) 사용
- 주 3회 격일 수행

## 2. 핵심 설계 원칙

> **타이머가 주인공이고, AI는 보조 심판이다.**

이 원칙에서 모든 결정이 파생된다.

1. **AI는 절대 운동을 막지 않는다.** AI 판정과 무관하게 타이머는 항상 흐른다.
2. **AI가 실패하면 조용히 물러난다.** 에러 메시지·중단 없이 순수 타이머 모드로 전환한다.
3. **수동 경로가 항상 존재한다.** 화면 아무 곳이나 탭하면 다음 단계로 진행한다.
4. **영상은 기기 밖으로 나가지 않는다.** 전송·저장하지 않는다. 관절 좌표만 실시간 계산 후 폐기한다.
5. **서버가 없다.** 로그인·계정·DB 없음. 기록은 기기 내부 저장소에만 존재한다.

## 3. 운동 프로그램 정의

`js/routine.js` 한 파일에 데이터로 선언한다. 이 파일의 숫자만 바꾸면 앱 전체가 따라간다.

|---|---|
| 어깨 회전 | 40초 |
| 팔목·발목 돌리기 | 40초 |
| 제자리 걷기 | 50초 |
| 맨몸 스쿼트 10회 | 50초 |

합계 180초.

### 3.2 메인 (19분)

| 순서 | 종목 | 수행 | 세트 | 세트간 휴식 |
|---|---|---|---|---|
| 1 | 데드행 (매달리기) | 25초 | 3 | 60초 |
| 2 | 팔굽혀펴기 | 12회 (제한시간 60초) | 3 | 90초 |
| 3 | 딥스 버티기 | 20초 | 3 | 60초 |

## 4. 화면 설계

화면은 3개뿐이다.

### 4.1 홈 화면

- 중앙: 「오늘 운동 시작」 대형 버튼. 오늘이 운동일이면 강조 표시.
- 상단: 이번 주 달력. 수행한 날은 채워짐.
- 하단: 「연속 N일째」 한 줄 + 최근 기록 요약.
- 회복일이면 "오늘은 회복일입니다" 안내 문구 표시 (버튼은 여전히 동작).
- 설정: **「AI 끄기」 토글** (그날은 순수 타이머로만 동작), 「자리 잡기 다시 하기」.

### 4.2 운동 화면

폰 방향: **가로(landscape) 기본.** 전신이 더 잘 들어온다.

- 배경: 전면 카메라 전체화면, 좌우 반전(거울 모드).
- 오버레이 (반투명):
  - **상단** — `데드행 · 2세트 / 3`
  - **중앙** — 남은 초. 화면 높이의 약 1/3 크기. 2~3m 거리에서 곁눈질로 읽혀야 한다.
  - **하단** — 25분 전체 진행바 + `다음: 휴식 60초`
- **화면 어디든 탭 = 다음 단계로 즉시 진행.**
- Wake Lock으로 25분간 화면이 꺼지지 않는다.

### 4.3 완료 화면

- 오늘 수행 요약 (종목별 세트별 실측치)
- 성장 그래프 3종
- 마무리 문구 한 줄

## 5. 음성 코칭

- 브라우저 내장 `speechSynthesis` (한국어). 갤럭시 크롬에서 동작.
- **음성이 주 안내자다.** 폰이 2~3m 떨어져 있어 화면 글씨는 읽히지 않는다는 전제.

발화 시점과 문구 유형:

| 시점 | 예시 |
|---|---|
| 세트 시작 전 | "데드행, 두 번째 세트. 준비… 셋, 둘, 하나, 시작." |
| 수행 중 (10초/5초 남음) | "10초 남았습니다", "좋습니다, 5초" |
| 팔굽혀펴기 카운트 | "하나… 둘… 셋…" |
| 세트 종료 | "완료. 60초 휴식하세요." |
| 휴식 종료 10초 전 | "10초 뒤 시작합니다. 자리로 오세요." |
| 자세 이탈 (1회만) | "자세 유지하세요" |
| 조기 종료 | "25초 목표에 19초. 다음 세트에 조금만 더." |
| AI 물러남 | "잘 안 보이네요. 시간만 재겠습니다." |

문구는 전부 `js/coach.js` 한 곳에 모은다.

## 6. AI 판정 설계

### 6.1 엔진

- **MediaPipe Pose Landmarker** (구글, 브라우저 내 WebGL 실행). 33개 관절점, 약 30fps 목표.
- 모델은 경량(lite) 버전을 사용한다. 정확도보다 안정적 프레임레이트가 중요하다.

### 6.2 종목별 판정 규칙

각 규칙은 `js/judges/` 아래 종목당 1파일. **관절 좌표를 입력받아 상태를 반환하는 순수 함수**로 작성한다 (카메라 없이 테스트 가능하게).

#### ① 데드행

- **매달림 조건**: 양 손목 y좌표가 양 어깨 y좌표보다 위 + 양 발목이 "자리 잡기" 시 저장한 착지 발목 높이보다 유의미하게 위로 떠 있음
- **자동 시작**: 매달림 조건이 성립하는 순간 세트 타이머 시작. 준비 시간이 깎이지 않는다.
- **자동 시작 타임아웃**: "준비" 카운트다운 종료 후 **15초 안에 매달림이 감지되지 않으면** 그냥 타이머를 시작한다. (기구에 이미 매달린 채 시작했거나 인식이 안 되는 경우에도 세션이 멈추지 않게.)
- **종료 조건**: 손목이 어깨 아래로 내려옴 → 타이머 정지, 실측 시간 기록

#### ② 팔굽혀펴기 (유일한 반복 카운트 종목)

- **측정값**: 어깨-팔꿈치-손목이 이루는 각도
- **상태 기계**: `UP`(각도 ≥ 150°) → `DOWN`(각도 ≤ 100°) → `UP` 왕복 1회를 1회로 계산
- 부분 가동범위(중간에서 되돌아감)는 카운트하지 않는다. 초보에게 중요한 지점.
- **세트 종료**: 목표 12회 도달 **또는** 제한시간 60초 경과 중 먼저 오는 쪽

#### ③ 딥스 버티기

- **기준 높이**: "자리 잡기"는 데드행 자세만 저장하므로 딥스에는 쓸 수 없다. 대신 **각 세트 시작 직후 1초 동안의 평균 어깨 y좌표**를 그 세트의 기준으로 삼는다. (세트마다 다시 잡으므로 폰이 조금 밀려도 영향이 없다.)
- **측정값**: 어깨 y좌표가 그 세트 기준 높이에서 유지되는가
- **이탈 판정**: 기준보다 유의미하게 내려감 → "자세 유지하세요" 1회 경고
- **종료 조건**: 경고 후에도 이탈 상태가 지속되면 세트 종료, 그 시점까지 기록

#### ④ 다리 들어올리고 버티기

- **측정값**: 무릎 y좌표가 엉덩이 y좌표보다 위에 있는가
- **종료 조건**: 무릎이 엉덩이 아래로 내려감
- 미세한 흔들림은 허용 (아래 디바운스 규칙 적용)

### 6.3 오작동 방지 장치

**(1) 자리 잡기 (캘리브레이션)**

첫 실행 시 1회 수행. 이후 홈 화면 설정에서 재실행 가능.

> "폰을 놓은 자리에서 치닝디핑 기구에 한번 매달려 보세요. 3초만 그대로."

이 3초 동안 해당 환경(조명·각도·거리·기구 위치)에서의 기준 좌표를 저장한다. 이후 모든 판정은 절대 좌표가 아닌 **이 기준선과의 상대 비교**로 수행한다.

기구 위치나 폰 자리를 옮기면 다시 수행한다.

**(2) 디바운스**

단일 프레임 판정을 신뢰하지 않는다. **동일 상태가 연속 5프레임(약 0.15초)** 유지되어야 상태 전환을 인정한다. 순간적인 가림·튐으로 인한 오판을 막는다.

**(3) 저조도 대응 (Graceful Degradation)**

- 관절 인식 신뢰도가 임계값 아래로 3초 이상 지속 → 해당 **세트에 한해** AI를 끄고 순수 타이머로 전환. 음성 1회 안내.
- 다음 세트에서 다시 시도한다. 한 번 실패했다고 세션 전체를 포기하지 않는다.

### 6.4 조정 가능한 상수 (초기값)

아래 값은 전부 한 파일(`js/judges/thresholds.js`)에 모아 둔다. 실제 야간 환경에서 돌려보고 조정하는 것을 전제로 한 **초기 추정치**이며, 코드를 뜯지 않고 이 파일만 고쳐 튜닝한다.

| 상수 | 초기값 | 용도 |
|---|---|---|
| `DEBOUNCE_FRAMES` | 5 | 상태 전환 인정에 필요한 연속 프레임 수 |
| `POSE_CONFIDENCE_MIN` | 0.5 | 관절 인식 신뢰도 하한 |
| `LOW_CONFIDENCE_TIMEOUT` | 3초 | 이 시간 이상 신뢰도 미달 시 AI 물러남 |
| `HANG_DETECT_TIMEOUT` | 15초 | 데드행 자동 시작 대기 한계 |
| `PUSHUP_ANGLE_UP` | 150° | 팔 편 상태 판정 |
| `PUSHUP_ANGLE_DOWN` | 100° | 팔 굽힌 상태 판정 |
| `PUSHUP_TIME_LIMIT` | 60초 | 팔굽혀펴기 세트 제한시간 |
| `DIPS_BASELINE_WINDOW` | 1초 | 딥스 기준 높이 산출 구간 |
| `POSTURE_DROP_RATIO` | 화면 높이의 8% | "유의미하게 내려감" 기준 |
| `POSTURE_GRACE` | 2초 | 경고 후 세트 종료까지 유예 |

**(4) 수동 우선**

- 화면 탭 = 무조건 다음 단계 (AI 상태 무관)
- 홈 화면 「AI 끄기」 토글로 세션 전체를 순수 타이머 모드로 실행 가능

## 7. 기록과 그래프

### 7.1 저장 형태

기기 내부 저장소(localStorage 또는 IndexedDB)에만 저장. 하루 1레코드.

```
2026-07-21
  데드행      22초 / 24초 / 19초   [실측]
  팔굽혀펴기  12회 / 11회 / 9회    [실측]
  딥스        20초 / 20초 / 16초   [실측]
  레그레이즈  20초 / 18초 / 15초   [실측]
  총 소요 24분 38초 · 전부 완료
```

### 7.2 실측 vs 추정 구분 (중요)

각 세트 기록에는 **출처 플래그**가 함께 저장된다.

- `실측` — AI가 판정한 값
- `추정` — AI가 물러나서 목표치를 그대로 기록한 값

그래프에서 이 둘을 시각적으로 구분한다(실측 = 진한 색, 추정 = 연한 색). **구분하지 않으면 성장 그래프가 거짓말을 하게 된다.**

### 7.3 그래프 3종

많으면 보지 않는다. 3개로 제한한다.

1. **데드행 최고 기록** 주별 추이 — 악력·상체 지구력 지표
2. **팔굽혀펴기 총 횟수** 주별 추이 — 근력 지표
3. **주간 수행 횟수** — 목표선 3회를 점선으로 표시

SVG로 직접 그린다. 차트 라이브러리를 쓰지 않는다.

## 8. 기술 구성

순수 HTML/CSS/JavaScript. 빌드 도구·프레임워크 없음. (기존 `neon-fleet` 프로젝트와 동일한 방식)

| 부품 | 역할 |
|---|---|
| MediaPipe Pose Landmarker | 관절 인식 (기기 내 실행, 전송 없음) |
| Web Speech API (`speechSynthesis`) | 한국어 음성 코칭 |
| Screen Wake Lock API | 25분간 화면 꺼짐 방지 |
| `getUserMedia` | 전면 카메라 |
| localStorage / IndexedDB | 기록 저장 |
| SVG (직접 작성) | 그래프 |

### 8.1 파일 구조

```
night-workout/
  index.html
  manifest.json          ← 홈 화면 아이콘용 (PWA)
  css/
    style.css
  js/
    routine.js           ← 운동 프로그램 데이터. 루틴 변경은 여기만
    timer.js             ← 타임라인 엔진 (순수 로직)
    coach.js             ← 음성 문구 + 발화
    camera.js            ← 카메라 + MediaPipe 래퍼
    judges/
      deadhang.js
      pushup.js
      dips.js
      legraise.js
      debounce.js        ← 공통 디바운스 유틸
      thresholds.js      ← 조정 가능한 상수 모음 (6.4절). 튜닝은 여기만
    calibration.js       ← 자리 잡기
    storage.js           ← 기록 저장/불러오기
    charts.js            ← SVG 그래프
    app.js               ← 조립 + 화면 전환
  tests/
  docs/
```

**모듈 경계 원칙**

- `timer.js`와 `judges/*`는 **DOM·카메라를 모르는 순수 로직**이다. 입력을 받아 상태를 반환할 뿐이다.
- `camera.js`는 관절 좌표를 뽑아 넘겨줄 뿐, 판정하지 않는다.
- `app.js`만이 이 조각들을 알고 조립한다.

이 경계 덕분에 판정 로직을 카메라 없이 테스트할 수 있다.

### 8.2 배포

카메라 접근에는 HTTPS가 필요하다. 파일 직접 복사 방식은 불가능하다.

- **GitHub Pages**에 배포한다. 무료이며 HTTPS가 자동 제공된다.
- 폰 크롬에서 해당 주소를 열고 「홈 화면에 추가」 → 이후 아이콘으로 실행.
- 저장소는 공개(public)로 둔다. 코드에는 개인정보가 없고, 운동 기록·카메라 영상은 기기 내부에만 존재한다.

## 9. 테스트 전략

### 9.1 자동 테스트 (카메라 불필요)

판정 로직과 타이머가 순수 함수이므로, 가짜 입력으로 검증한다.

- **판정**: 합성 관절 좌표를 입력해 기대 상태가 나오는지 확인
  - "손목이 어깨 위 + 발이 뜸" → 매달림으로 판정되는가
  - "팔이 130°까지만 굽음" → 카운트되지 않는가
  - "1프레임만 튐" → 디바운스로 무시되는가
  - "신뢰도 임계값 이하 3초" → 타이머 모드로 전환되는가
- **타이머**: 시간을 주입해 전체 25분 타임라인이 올바른 순서·시각에 이벤트를 내는지 확인
- **기록**: 실측/추정 플래그가 올바르게 저장·구분되는지 확인

### 9.2 수동 확인 (실제 기기)

각 단계 완료 시 실제 야간 환경에서 1회씩 수행한다.

- 갤럭시 크롬에서 카메라 권한·음성·화면 유지 동작
- 실제 조명에서의 인식률
- 2~3m 거리에서 화면 숫자 가독성

## 10. 구현 단계

한 번에 전부 만들지 않는다. **각 단계 완료 후 실제 운동에 며칠 사용해보고** 다음으로 넘어간다.

구현 계획(implementation plan)도 단계별로 따로 작성한다. **가장 먼저 작성할 계획은 1단계 하나만 다룬다.** 1단계를 실제로 써본 뒤 나온 피드백이 2단계 계획의 입력이 된다.

### 1단계 — 확실히 작동하는 타이머 (AI 없음)

25분 자동 진행, 음성 코칭, 화면 꺼짐 방지, 홈 화면 아이콘(PWA), 기록 저장.

**이 시점부터 매일 실사용이 가능하다.** 실제로 며칠 써보면 "휴식 90초가 너무 길다" 같은 것이 몸으로 드러난다. 그 피드백을 2단계 전에 반영한다.

### 2단계 — 카메라와 AI 심판

거울 화면, 자리 잡기, 4종목 판정, 데드행 자동 시작, 저조도 시 물러나기, AI 끄기 토글.

밤 조명에서의 실제 인식률이 여기서 판가름 난다. 인식률이 실용 수준에 못 미치면 1단계 결과물만으로도 앱은 완결적으로 동작한다.

### 3단계 — 그래프와 다듬기

성장 그래프 3종, 달력, 연속일수, 음성 문구 정리.

## 11. 명시적 비목표 (YAGNI)

다음은 **만들지 않는다.**

- 계정·로그인·클라우드 동기화
- 다중 사용자
- 운동 영상 녹화·저장
- 소셜 공유·랭킹
- 다른 운동 프로그램·종목 라이브러리
- 네이티브 앱(스토어 배포)
- 알림·리마인더 (1단계~3단계 범위 밖. 필요해지면 그때 논의)
